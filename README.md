# Маркетинг-игра

Обучающая игра для студентов и начинающих маркетологов. За полчаса вы проводите одну рекламную кампанию районной кофейни: от разговора с владельцем до отчёта.

Термины вроде сегмента, CPM, UTM и посева участникам обычно уже знакомы. Здесь можно потренироваться применять их к конкретной задаче клиента, когда напротив сидит владелец с ограниченным бюджетом и нужно понять, о чём спросить первым, кого звать и как потом объяснить, сработало или нет.

## Для кого

Студенты и люди, которые только входят в профессию. Первая версия рассчитана на тех, кто знает отдельные понятия и пока затрудняется собрать из них работу для местного бизнеса. Вводного курса по терминам здесь нет, и людям с крупными бюджетами этого будет мало.

## Как устроено

На главной — карта тем. Их можно открывать в любом порядке, заранее ничего не закрыто.

1. **Бриф.** Договориться о результате, сроке и бюджете.
2. **Аудитория.** Выбрать, кто реально может зайти днём.
3. **SMM и контент.** Собрать публикацию, по которой можно прийти.
4. **Блогеры.** Посмотреть данные автора и условия выхода до оплаты.
5. **Медиаплан.** Отличить дешёвый показ от показа рядом с точкой.
6. **Аналитика и отчёт.** Разделить кассу, коды и эффект рекламы.

В теме несколько карточек с объяснением и короткая практика. Тексты взяты из уроков кейса. За долю верных ответов до подсказки тема получает от 0 до 3 звёзд. Лучший результат сохраняется, тему можно пройти заново и улучшить его.

Ниже на той же странице — кейс кофейни «Пауза». Владелец хочет больше гостей в будни с 14 до 17. Это связанные пять уроков: бриф, аудитория, публикация, медиаплан и отчёт. После каждого урока — квиз из четырёх вопросов. Решения меняют условный бюджет и итоговые цифры. Звёзды тем на этот расчёт не влияют. Два выбора — выгрузка кассы до запуска и коды на чеках — сами продажи не добавляют; их пользу видно только в финальном отчёте.

Все суммы, проценты и результаты учебные. Это модель для практики, не прогноз для живой кофейни.

Прогресс тем, звёзд и кейса сохраняется в браузере (и в Expo Go). Можно закрыть вкладку и вернуться к тому же шагу. Старое сохранение кейса, сделанное до карты тем, по-прежнему открывается.

Содержание первой кампании собрано по «Учебнику по медиапланированию» и лежит в `src/content/campaigns/campaign-coffee.json`.

## Стек

- React Native и Expo — одна кодовая база для iOS, Android и веба.
- Веб-версия собирается для Vercel и должна открываться с телефона по публичной ссылке.
- Уроки, квизы и параметры симуляции описаны в JSON, чтобы новые материалы можно было добавлять, не переписывая весь движок.

## Какие инструменты ИИ использовались

- **ИИ-ассистент** — продуктовый пакет первой кампании, сценарий уроков, правила симуляции и тексты квизов.
- **Cursor cloud agent** — код приложения в этом репозитории.

## Как запустить локально

Нужны Node.js (LTS) и npm.

```bash
npm install
npx expo start
```

В терминале Expo можно открыть веб-версию или запустить приложение в Expo Go на телефоне (QR-код из того же терминала).

Проверить типы, стиль и расчёт модели:

```bash
npm test
npm run typecheck
npm run lint
```

Собрать статическую веб-сборку:

```bash
npm run build:web
```

Команда пишет папку `dist`. Её забирает Vercel: в репозитории уже есть `vercel.json` с этой папкой и перезаписью маршрутов на `index.html`.

Номер счётчика Яндекс Метрики, когда он появится, кладётся в `EXPO_PUBLIC_YM_COUNTER_ID` (см. `.env.example`). Без номера игра работает, цели просто не отправляются.

## Как идёт разработка

Каждую новую возможность делаем в отдельной ветке и вливаем в основную через pull request с коротким описанием: что изменилось и как это проверить. В основную ветку напрямую не коммитим.

Так проще читать историю проекта и привыкнуть к базовым словам: ветка, коммит, pull request.

Как устроены папки, новая кампания и сохранение шага — в [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md).
